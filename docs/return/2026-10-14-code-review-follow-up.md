## R10：带键 ForEach 在单项与多项之间切换时重置已有项目状态

- 优先级：P1
- 状态：已修复（2026-10-14）
- 位置：[Reconciler.cs](../../src/CSharp.UI/Runtime/Reconciler.cs)，第 128—136 行，`BuildComponent()`。
- 分类：R08 的隐式容器修复引入的身份变化。

**复现步骤：**

1. 定义组件，`Build()` 直接返回 `ForEach<int>`，项目使用自身 ID 作为稳定键；初始项目为 `[1]`。
2. 每个项目视图是持有 `UseState("value", 0)` 的组件。将项目 1 的状态改为 42，并完成一次更新。
3. 添加项目 2，使集合成为 `[1, 2]`；触发父组件重建。
4. 在两个项目状态下，再将项目 1 的状态改为 77，删除项目 2并再次重建。

**实际结果：**

```text
KEYED_SINGLE_TO_MANY: sameNode=False, state=0, expected=42
KEYED_MANY_TO_SINGLE: sameNode=False, state=0, expected=77
```

**预期结果：** 项目 1 的键与视图类型没有变化，添加或删除其他项目时应保留原节点及状态，分别仍为 42、77。

**原因与影响：** 单项展开直接成为组件子节点，多项展开却改为 `ImplicitRootContainer` 的子节点。项目数量跨越 1 的边界时，协调器看到父级结构和节点类型变化，卸载整棵旧子树后重新创建。稳定键只在同一父级内匹配，无法抵消本次容器切换，因此普通列表增删会清空既有组件状态；焦点、滚动和编辑状态也有同类风险。

**现有回归测试遗漏：** `R08_RootForEach_HandlesEmptySingleAndReorder` 验证了数量变化后的布局和键值，但没有在单项与多项之间切换时验证已有项目的节点引用与状态是否保留。键值相同不代表节点身份相同。

**修复建议：** 为直接返回的 `ForEach` 保持稳定的容器边界，使同一集合在空、单项和多项时不因条目数量改变节点层级。普通单视图组件的现有行为应保持一致，保留集合的显式键及前缀键语义。

**回归验收：**

- [x] 带键集合 `[1] → [1, 2] → [1]` 过程中，项目 1 节点引用和命名状态保持不变。
- [x] 验证两项删至另一单项、单项增加新项及项目重排，不仅检查最终的 Key 值。
- [x] 聚焦输入框所在项目在上述增删过程中保留合法焦点和编辑状态。
- [x] 空集合、单项及多项仍正确布局；真正被删除的项目照常卸载并释放资源。
- [x] 原 R04、R08 的协调更新及布局测试继续通过。

## R11：长度限制拒绝整个插入字素时，仍删除原选区

- 优先级：P2
- 状态：已修复（2026-10-14）
- 位置：[TextField.cs](../../src/CSharp.UI/Views/TextField.cs)，第 556—561 行，`ReplaceSelection()`；提交文本和粘贴路径均调用该方法。
- 分类：R05 的剩余容量与字素截断修复未覆盖的拒绝路径。

**复现步骤：**

1. 输入框内容为 `ab`，设置 `MaxLength=2`。
2. 聚焦输入框，用 Home 和 Shift+Right 选中 `a`。
3. 提交 `😀`，或将 `😀` 放入剪贴板后粘贴。

**实际结果：**

```text
REJECT_SELECTION input: actual=b, expected=ab
REJECT_SELECTION paste: actual=b, expected=ab
```

**预期结果：** 替换后可插入容量为 1 个 UTF-16 码元，无法容纳 2 个码元的完整字素。输入应被整体拒绝，保留原文本 `ab` 及原选区，不应等价于删除选区。

**原因与影响：** `FitInsertion()` 返回空字符串后，`ReplaceSelection()` 仍将空内容拼接到选区两端，从而删除选中字符并折叠光标。没有选区的输入和粘贴路径已有空插入提前返回，但选择替换路径没有相同保护。用户只是在长度限制下尝试输入，仍会丢失原有内容。

**现有回归测试遗漏：** 当前测试覆盖无选区的完整字素拒绝、选区替换能部分放入普通字符及容量用尽后的普通粘贴，未覆盖有选区且第一个完整字素也放不下的情况。

**修复建议：** 区分因容量限制被拒绝的插入与用户明确执行删除。非空输入经容量限制变为空时，应保留文本、光标及选区；Backspace、Delete、剪切等显式删除仍按原语义执行。输入与粘贴保持一致。

**回归验收：**

- [x] 上述输入与粘贴用例均保持 `ab` 和原选区不变。
- [x] 使用组合字符 `e + U+0301` 验证同样的完整字素拒绝行为。
- [x] 覆盖拒绝发生在文本开头、中间及末尾的选区场景。
- [x] 部分可放入内容仍按字素边界接受，例如原 R05 的 `abcd` 选中 `a` 后输入 `XYZ` 仍得到 `Xbcd`。
- [x] 显式删除、剪切、无选区输入及粘贴测试继续通过。
