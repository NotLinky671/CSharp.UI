## 目标与范围

让组件读取状态自动建立依赖，状态变化后合并重建相关组件，并提供输入控件的双向绑定。

实现 UI 线程内的状态运行时与调度抽象；真实窗口唤醒由任务 06 接入。

## 前置依赖

- 前置任务：[任务 03：视图描述、组件与节点协调更新](03-view-reconciliation.md)。
- 接入依据：使用任务 03 的组件构建上下文、持久节点和卸载机制，以及任务 02 的调度契约。

## 实施清单

- [x] 实现 Component.UseState(name, initialValue)，状态由运行时组件节点保存；相同名称在重建时复用 State<T>。
- [x] 实现 State<T>.Value 与 Binding<T> 读写桥接；按 EqualityComparer<T>.Default 判断实际变化。
- [x] 构建期间追踪 State 读取，构建结束更新依赖集合；条件变化后移除不再读取的依赖，卸载时释放所有订阅。
- [x] 把相关组件置为待更新，合并一轮事件中的多次变化；构建与协调更新由调度阶段执行，避免通知期间递归 Build。
- [x] 提供 UiDispatcher.Post(action)，后台调用入队，动作在 UI 线程执行；后台直接修改状态给出线程约束诊断。
- [x] 保护 UseState 的组件构建上下文和同名状态类型一致性；用测试调度器验证生命周期及投递行为。

## 公开 API 与交接

交付 State<T>、Binding<T>、Component.UseState<T>() 与 UiDispatcher.Post(action)；状态更新不要求应用手动重绘。

交付实现、对应测试及必要使用说明；所有测试与实现同步完成。后续任务消费本任务契约时保持原计划的模块边界。

## 测试与验收

- [x] 组件重建后命名状态仍保持原值；新身份节点使用初始值，旧节点卸载后订阅释放。
