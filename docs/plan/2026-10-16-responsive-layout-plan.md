## 1. 目标与范围

让应用能声明“空间充足时横向排列，空间不足时换行、压缩或改为纵向”，由框架根据父容器提供的空间重新布局。能力适用于窗口、侧栏、卡片、嵌套容器与滚动内容，不能只读取主窗口尺寸来给 Gallery 写特殊判断。

本计划交付五项互补能力：

| 能力 | 拟议 API | 解决的问题 |
|---|---|---|
| 弹性空间分配 | `.Flex(...)`、`.FillWidth()` | 输入框、滑块等在可用空间内伸缩 |
| 自动换行 | `Flow` | 按钮组、标签和工具项在窄容器中分行 |
| 稳定的布局切换 | `AdaptiveStack` | 保留相同子节点，仅切换横向/纵向排列 |
| 容器宽度响应 | `Responsive`、`ResponsiveInfo` | 根据父容器宽度选择不同内容结构 |
| 示例与验证 | Gallery、独立布局测试、图形/交互回归 | 验证实际页面与嵌套布局，而非只展示 API |

默认边界：首先支持基于**逻辑可用宽度**的响应式布局；高度按内容自然展开，尤其兼容纵向 ScrollView。通用高度断点、自动网格、完整 CSS Flexbox、动画过渡、容器查询样式语言、虚拟化与任意跨父级状态迁移不在本轮范围。

沿用 .NET 10 / C# 14、OpenTK/OpenGL 和 SkiaSharp/HarfBuzz。核心 API 继续不暴露后端类型。

## 2. 当前行为与兼容原则

- Gallery 写死了 360/320 宽的文本、240 宽的输入框，以及若干无法换行的 HStack；窄窗口出现横向溢出是现有声明的直接结果。
- HStack 在主轴上以无界约束测量子项，只给 Spacer 分配正的剩余空间，没有压缩或换行算法。
- 固定 Frame 会给子项传递明确宽度。不能把所有固定宽度暗中改成“尽可能压缩”，否则既有尺寸与修饰符顺序语义会变化。
- Key 当前只在同级节点中匹配。把 HStack 描述换成 VStack，或把控件移动到另一父节点下，不能据此保证控件身份保持。
- R18 已允许窗口回调期间同步处理必要布局。响应式内容切换必须加入受控的更新阶段，不能在 Measure/Arrange 中直接执行任意用户构建和修改节点树。

保持现有 HStack/VStack/Frame 的默认行为；伸缩、换行和自动切换均通过新 API 显式启用。未声明伸缩的固定控件仍可能溢出；这是需要由应用处理的布局选择，应有可定位的调试诊断。

## 3. 空间、断点与测量约定

1. 断点依据父级扣除 Padding 等修饰后提供的逻辑宽度，不能使用物理像素、屏幕分辨率或全局窗口宽度。同一容器的逻辑宽度相同，100%/125%/150%/200% DPI 下选择应相同。
2. 允许应用自定义断点，不内置手机/平板设备分类。本轮示例使用 560 和 840 作为演示阈值，业务代码可以选择其他值。
3. 阈值采用确定规则：宽度 `< breakpoint` 为窄布局，`>= breakpoint` 为宽布局；不添加隐式迟滞。断点精确值、两侧小量与连续拖拽都要测试。
4. 区分有界与无界约束。垂直 ScrollView 限制内容宽度、释放高度；水平 ScrollView 释放宽度。宽度无界时不得用 0、屏幕宽度或任意大常数冒充，需明确进入无界策略。
5. 保留小数逻辑尺寸，不能为断点或累计布局误差按物理像素粗暴取整；R16/R17 的文字像素映射与颜色遮罩契约继续成立。
6. 弹性测量会包含自然尺寸探测和最终宽度复测。框架内部要区分探测与有效布局提案，避免探测过程触发 Responsive 分支挂载、状态订阅和卸载。

## 4. 弹性尺寸

拟议用法：

```csharp
new HStack(
    new Text("单行输入"),
    new TextField(name.ToBinding(), "请输入内容")
        .Flex(grow: 1, shrink: 1, basis: 240, min: 120))
    .Spacing(8);

new Text("根据父容器实际可用宽度换行的说明文字")
    .Wrap()
    .FillWidth();
```

`.Flex(grow, shrink, basis, min, max, axis)` 中的长度是逻辑长度；basis 省略表示自然尺寸，min 默认 0，max 默认正无穷。axis 默认 `FlexAxis.Main`，也可指定 Horizontal/Vertical；后两者在 AdaptiveStack 切换时保持轴向不变，避免输入框的“宽度 basis 240”意外变成“高度 240”。权重以及显式 basis/min 必须有限且非负，max 允许正无穷，所有参数禁止 NaN，min 不得大于 max，非法输入在声明时给出明确异常。

分配算法：

- 先测量自然尺寸/basis，将初始 basis 约束到 min/max 后扣除项目间距；未使用 Flex 的子项按既有尺寸处理。
- 有正剩余空间时按 grow 权重分配；某项达到 max 后冻结，将剩余量分配给其他可增长项。
- 空间不足时仅压缩明确设置 shrink 的子项，以 `shrink × 初始约束后 basis` 为权重；达到 min 后冻结并继续分配。min 为 0、basis 为 0 的项没有可压缩量，权重按 0 处理。
- 分配结束后按实际宽度重新测量文字和其他可换行子项，再计算行高并 Arrange。不能只挤压旧 Frame、沿用旧文本高度。
- 所有 min 与不可压缩项之和仍超过容器时，明确报告溢出；不使用负尺寸、不隐式丢弃控件、不无限重测。
- 主轴无界时不进行无穷剩余空间分配，使用自然尺寸或有限 basis。

`.FillWidth()` 是占用有界可用宽度的便利修饰：在横向 Stack 主轴上作为可增长、可压缩项参与分配，在 VStack 等交叉轴上占满可用宽度；无界宽度时回退自然尺寸。它不取消子树明确声明的固定 Frame。同轴嵌套多个 Flex/FillWidth 时，以外层声明为准、不叠加权重；不同轴独立处理。固定 Frame 的尺寸要求需作为明确的布局特征传播，不能从已经被父约束截短的 DesiredSize 反推“可压缩”。

固定宽度与弹性 basis 必须在文档中区分：希望“通常 240，但可以变窄”应使用 basis；`.Frame(width: 240)` 仍表示固定尺寸。显式固定子树阻止压缩时给出诊断，避免外层显示为压缩成功、内部仍溢出的假象。修饰符嵌套顺序与嵌套 Stack 的主轴归属须用契约测试固定。

## 5. 自动换行 Flow

```csharp
new Flow(
    new Button("保存", Save),
    new Button("另存为", SaveAs),
    new Button("取消", Cancel))
    .Spacing(8)
    .LineSpacing(8);
```

- 第一版采用按声明顺序、从左到右的贪心分行；当前行放不下下一项则换行。行间距与项间距分开设置，默认行内顶部对齐，可提供 Center/End 对齐。
- 每行按该行最高项目计算高度；换行后重新计算整体期望高度，供纵向滚动视图使用。
- 空容器、单项、正好放满、一项宽于整行、长单词、多行文本、带 Padding/Border 的子项均有明确行为。
- 单项大于整行时，可接受较窄约束的普通项按整行宽度重新测量；不可压缩固定项独占一行并报告溢出，不静默裁剪为“已适配”。
- 第一版 Flow 不接入逐行 Flex 权重分配，也不对最后一行自动拉伸；直接用于 Flow 子项的 grow/shrink 权重需给出不支持诊断，推荐用内嵌 HStack/AdaptiveStack 表达弹性表单行。无界宽度时排列为单行。
- 分行只改变子项 Frame，不创建“每行运行时父节点”；Key、输入状态、焦点和 Tab 顺序按原始子项顺序保持。

## 6. 稳定身份的 AdaptiveStack

```csharp
new AdaptiveStack(
    560, // 父级可用逻辑宽度小于 560 时改为纵向
    new Text("CSharp.UI 控件展示"),
    new Button("切换主题", SwitchTheme))
    .Spacing(12);
```

- 宽布局横向、窄布局纵向；默认交叉轴对齐及间距应与对应现有 Stack 一致，允许显式配置两种模式的对齐/间距。
- 该容器始终是同一个视图类型和运行时父节点，切换只改变测量与排列算法，不通过 HStack/VStack 子树互换实现。
- 所有子节点保持相同父级和身份；输入框文本、光标、选区、焦点、组件 UseState 与滚动状态在模式切换时保持。
- `FlexAxis.Main` 随两种主轴解释，显式 Horizontal/Vertical 保持原轴向；Spacer 的剩余空间行为沿用所处模式的 Stack 规则，在无界主轴中不扩展。提供避免“宽度 basis 变成高度”和“纵向 Spacer 意外占空白”的使用说明与回归。
- 无界宽度采用横向自然尺寸，不借用外层窗口断点；如果应用需要有界响应，应由上层分配宽度或加尺寸约束。

## 7. 任意内容分支的 Responsive

```csharp
// 在 Component.Build 内创建；name 等持久状态由外层组件持有。
new Responsive(info =>
    info.IsWidthBounded && info.AvailableWidth < 560
        ? BuildCompactForm(name.ToBinding())
        : BuildWideForm(name.ToBinding()))
    .FillWidth();
```

`ResponsiveInfo` 首版提供 AvailableWidth、IsWidthBounded，使用父容器有效的逻辑宽度。默认在有界宽度下占满所分配宽度，高度由内容决定；无界宽度以 `PositiveInfinity` 和 false 表达，应用必须能选择自然尺寸分支。

运行时接入是该能力的前置交付，不能把 builder 简单放进 Measure：

1. 测量只记录最终有效提案和待更新请求，不执行 builder、不直接协调或卸载节点。自然尺寸探测不激活候选内容；同节点一轮内多次提案合并为最终有效提案。
2. UiRuntime 在重建/布局之间的安全阶段消费请求，执行 builder、协调节点，然后重新布局。首次挂载和后续宽度变化使用同一机制；布局未稳定时不得提交半成品绘制命令。
3. 同一次更新中保存最后稳定输入，合并重复请求。设置有诊断的每节点收敛上限（初拟同节点重复重建 8 次），不能让正常嵌套深度或多个独立节点共用一个“全局 8 轮”而误报；整体工作预算须经嵌套与批量原型验证后冻结。发现提案/内容循环时记录节点路径和约束并报告错误，不静默沿用错误布局或忙等。无界探测与有限宽度复测的交替不能被误判为真正的分支切换。
4. builder 必须是纯描述构建：不得写状态、执行 IO 或操作窗口；UseState 仍只能由 Component.Build 创建。builder 读取已有 State 时，应在独立依赖跟踪作用域登记，并在状态变化时重新计算；不能让这些读取因发生在 Component.Build 之外而悄悄失效。
5. 为此扩展内部动态内容失效目标，使状态通知能区分普通组件重建与 Responsive 内容重建；保留既有 UseState 所有权和依赖清理语义。builder 异常、失效请求已过时、节点已卸载等路径须安全清理。
6. 任意结构切换使用当前 Reconciler 规则：仅同父级同 Key/类型的节点保证复用，跨父级或类型变化会卸载。Key 不提供跨布局树迁移能力。应用持久数据放在外层 State/Binding；需要保持焦点和编辑状态时优先 AdaptiveStack。
7. 不常驻挂载所有候选分支，也不让不可见分支进入输入、焦点、计时和资源管理。真正卸载的分支要清理依赖、捕获和焦点。

该阶段需先通过最小原型证明“安全阶段切换、依赖跟踪、提案收敛”三个契约，再冻结具体内部接口并推广到示例，不能用特殊节点判断掩盖测量阶段修改树的问题。

## 8. 示例改造与可观察行为

Gallery 作为主要验收页，但新能力还需有与 Gallery 无关的独立示例和测试。

- 页头窄时纵向排列，主题按钮始终可见且可点击。
- 文本示例按卡片实际内容宽度换行/省略。为演示限制宽度可保留 maxWidth，不能继续用固定 360/320 作为唯一约束。
- 按钮组使用 Flow；布局示例使用 AdaptiveStack 展示同一批子节点切换主轴。
- 滑块和输入框使用弹性宽度；窄到低于表单行可用下限时，标签与控件改为上下排列。
- 图片说明与状态文本跟随可用宽度换行，卡片高度按内容变化。
- 保留真实内层 ScrollView、两层滚轮路由、主题和所有首版控件演示；布局切换不重置上层状态。
- 以 320/480/768/1024 逻辑宽度验收常用窄/宽场景；这些是测试宽度，不是强制业务断点。低于声明最小尺寸的极端窄窗口允许明确溢出诊断，不承诺任何尺寸都容纳任意固定内容。

## 10. 验收标准

### 布局算法与运行时

- 有界/无界/零宽度、小数宽度、嵌套 Padding/Frame、相等断点、不同 grow/shrink、min/max 冻结、不可压缩溢出、可换行文字高度均有断言。
- 测试实际控件 Frame、文本排版宽度、行高与最终命中位置，不能仅重复 helper 内公式。新的可用宽度必须进入文本布局请求，不能只给旧纹理做缩放。
- Responsive 分支、状态读取与依赖清理、描述更新、卸载、过时请求、探测测量、循环诊断与异常均有回归；不得在 Measure 中递归调用 ProcessPendingWork/BuildFrame。
- 宽度连续改变时，布局轮数、分支重建次数和缓存条目有界。静止时不继续构建/测量/绘制；同一断点内 AdaptiveStack 不反复挂载子树。避免同宽测量因 selector/闭包身份而无意义全部失效。

### 状态与输入

- 同一 AdaptiveStack/Flow 中的 TextField 输入中文、选择文字、保留焦点，跨断点切换与换行后继续编辑，节点身份和选区保持。
- Responsive 中保留同父级 Key 的情况验证复用；真正跨父级/移除分支的情况验证卸载清理，外层 Binding 数据保留，但不虚构焦点自动迁移。
- 窄/宽切换后 Button、Toggle、Slider、TextField、Tab 顺序和嵌套滚轮路由正确；旧坐标和旧裁剪区域不可点击。

### 图形、DPI 与交付

- DPI 1/1.25/1.5/2 下，相同逻辑宽度得到相同布局选择；物理像素覆盖、文字颜色遮罩与新布局坐标一致。比较实际 CPU→GL 输出及裁剪，不能以“非黑帧”代替验收。
- R18 的回调绘制能在一次受控稳定过程后获得完整的新布局；窗口连续缩放、跨断点与组件重建重入不会呈现半成品树或再次产生黑边。
- 当前基线为 441 项测试，最终以实际新增后的完整结果为准，保留既有全部测试；三个示例 Debug/Release 均更新、DLL 副本匹配、Release 启动检查通过。
- 至少记录 Windows 当前 150% 下的实际窗口行为；macOS/Linux 无真机时明确区分编译、纯布局测试、离屏测试与原生验证。新增依赖、失效次数和性能变化在实施时记录实际数据，不预设未经测量的帧率承诺。
- 提供原尺寸宽/窄 Gallery 图、独立嵌套容器例子，以及已知限制。示例可用不等于框架能力已完成，所有通用 API 必须有独立回归。
