# 文本输入与编辑基础计划：IME、编辑事务与撤销重做

计划日期：2026-10-17

状态：实施中。本文及任务中的新接口为设计草案，TI-01 平台验证和 TI-02 契约复审通过后冻结；文档完成不表示功能已实现。

任务索引：[10 个实施任务](../task/README.md)。执行者：DeepSeek Harness；规划与代码审核：Codex。

## 1. 目标与当前基础

目标是在保留单行 TextField 现有 API、响应式布局与 OpenTK 渲染底座的前提下，补齐 Windows 中文输入的组合过程，并建立平台无关的编辑事务与有界撤销/重做。

截至规划时，TextField 将插入、剪贴板与删除分别写入 Binding；光标、选区、横向滚动保存在运行时节点中。InputRouter 仅向当前焦点派发 TextInputEvent；OpenTkInputAdapter 从窗口 TextInput 接收已提交字符。没有独立组合会话、预编辑状态、编辑历史或宿主候选窗定位接口。宿主 Escape 退出目前独立于控件是否消费按键，接入 IME 时必须一并处理。

上一轮已交付的 Flex、Flow、AdaptiveStack、Responsive 作为兼容基线。测试数量以实施启动时重新构建后的实际结果为准，历史参考为四套共639项；不得用数量不减少代替旧断言保留。

## 2. 范围与平台承诺

| 范围 | 本计划交付 | 验收要求 |
|---|---|---|
| 核心编辑模型 | 文本、选区、字素边界、原子替换、组合状态、撤销/重做 | 不引用 OpenTK/Skia/Windows，跨平台 CPU 测试 |
| TextField | 原位置绘制预编辑、活动段样式、组合光标、正确提交/取消 | 真实 Skia 与 GL，保留单行与现有 Binding 用法 |
| Windows | 完成当前可用微信输入法（WeType）的预编辑、系统候选窗锚点、提交/取消及快捷键隔离 | 真实本机输入法与窗口；合成消息仅作补充 |
| macOS/Linux | 验证接入限制、冻结能力查询和已提交文本回退，保证加载/编译隔离 | 分别记录编译、模拟核心、原生真机；不将回退称为完整 IME |

Windows 是本轮完整原生输入法的强制交付平台。其余平台不会因为共用核心就被标为完整支持。本轮不承诺所有第三方输入法、手写/语音、重转换、完整双向编辑、彩色 Emoji、密码输入、富文本、无障碍文本桥接、多窗口。字素安全包含代理对、组合字符、ZWJ 序列的边界编辑，不等于完整 Emoji 绘制。

## 3. TI-01：平台接入必须先过验证门槛

先检查项目实际加载的 OpenTK 4.9.4 与 GLFW 二进制版本和平台后端，不能从网上最新版能力反推当前依赖。输出自有测试窗口的消息时间线、普通字符与组合结果的来源，包含开始、更新、结果、结束、按键和重复字符路径。

Windows 优先验证 HWND 子类化 + IMM32 宽字符接口的最小接入，候选 UI 使用系统原生窗口。调查当前可用输入法是否通过 IMM 兼容路径提供完整所需数据；如果不足，再比较 TSF 接入的工作量和必要性。不能预先承诺 IMM 覆盖全部 TSF 输入法，也不能在原型中替换整个 GLFW 事件循环。需要升级/替换窗口库、引入平台二进制或扩大 TSF 范围时，先写决策记录交 Codex 复审，受影响任务不得凭猜测开始。

macOS 调查实际 GLFW NSView 与 NSTextInputClient 的 marked text、replacement range、候选矩形查询及回调所有权；禁止未经验证覆盖 delegate 或全局方法交换。Linux 分开记录 X11/XIM 与 Wayland 输入协议及上下文取得限制，不把 X11 的实现当作 Wayland 支持。明确字符串/范围的原生单位，映射到核心 UTF-16；对无法在现有栈安全接入的部分提供能力回退。

原型只挂接自己创建的窗口，回调同 UI 线程；委托固定生命周期，关闭和异常路径恢复原过程，原生回调不让托管异常越界。证据保存在 docs/agents-notebook 的带日期决策记录及配套目录中，不把必须复用的唯一工具放在可清理 artifacts 下。

通过门槛（2026-10-17 用户范围修订）：用户已移除微软拼音并明确不要求测试，不安装、启用或测试该输入法。现有 WeType 真实预编辑及单次中文结果、独立探针86项测试与平台矩阵支持通过 TI-01 的接入路线审核，允许开始 TI-02。系统候选实际定位、取消和生产宿主完整联调尚未通过，转由 TI-07/TI-10 使用当前可用输入法验证；模拟测试不代替这些真实验收。

## 4. 架构与职责

| 模块 | 职责与接入点 |
|---|---|
| CSharp.UI 核心 | 编辑文档与选区、版本、组合会话、历史、焦点文本客户端、处理结果；InputRouter/UiRuntime 连接当前节点 |
| CSharp.UI.Text | 复用 Skia/HarfBuzz 测量显示文本、字形和 caret 几何；UTF-16 与字素映射 |
| CSharp.UI.OpenTK | 文本输入服务、Windows 消息桥、能力报告、平台单位转换、系统候选窗锚点、键盘所有权 |
| TextField | 从状态生成显示串、预编辑修饰、命中映射、横向滚动与渲染命令；禁止直接调用原生窗口 API |

输入路径：原生事件 → 平台适配与归一化 → 当前文本会话 → 编辑事务/组合更新 → 节点失效 → 安全重建/布局 → 显示串与caret → 宿主候选锚点。原生消息数据当场复制后排队，不能在不安全回调里递归 BuildFrame、布局或泵事件；但阻止默认重复插入所需的消息处理结果须同步返回。布局完成后再发布几何，原生回调内不得读取半成品树。

## 5. 候选契约与 API 边界

以下名称用于讨论，TI-02 可在保持语义的前提下精简或调整；不为测试扩大公共 API。

| 候选类型/入口 | 必须表达的语义 |
|---|---|
| TextSelection | Anchor/Active 的 UTF-16 偏移，保留方向；合法选区端点位于字素边界 |
| EditOperation / EditResult | 替换范围、插入串、前后选区、原因、文档版本、实际接受结果；单次原子变更 |
| CompositionUpdate | 焦点会话ID、组合ID、次序/版本、替换区、预编辑串、组合caret及分段属性 |
| ITextInputClient | 当前文本/选区快照、版本、组合更新/结果/取消和有效caret几何；只给实际焦点编辑节点 |
| ITextInputService | 开始/结束会话、取消、发布客户端几何、能力查询；测试无窗口实现和回退实现 |
| TextInputCapabilities | 已提交文本、组合输入、候选锚点分别声明；缺失和失败有可观察诊断 |
| 编辑命令 | Undo/Redo/Cut/Copy/Paste/SelectAll 的统一内部派发；优先复用 TextField 现有入口 |

核心契约只使用框架自己的字符串、范围、矩形和值类型，不暴露 HWND/HIMC/NSView、OpenTK、Skia 类型。继续支持 TextInputEvent 与现有 TextField(Binding<string>, placeholder)；组合事件单独建模，不给旧的上屏事件换含义。草案不新增应用必须持有的编辑器对象；历史默认归运行时节点所有。是否需要公开历史容量选项在 TI-02 冻结，先保证内部可配置、可测。


现有应用入口保持不变，以下用法继续有效；组合输入由宿主能力自动接入，不要求应用逐项处理原生消息：

```csharp
using CSharp.UI;

public sealed class NameForm : Component
{
    protected override View Build()
    {
        var name = UseState("name", string.Empty);
        return new VStack(
            new Text("名称"),
            new TextField(name.ToBinding(), "输入中文名称").FillWidth())
            .Spacing(8)
            .Padding(16);
    }
}
```

这段代码只展示既有API兼容目标；当前版本仍仅接受已提交文本，不能因示例可运行而宣称已支持组合输入。内部服务和新事件的确切C#签名由TI-02冻结并在指南更新。

## 6. 编辑事务、Binding 与 Unicode

所有插入、删除、选区替换、剪切/粘贴、IME结果、Undo/Redo通过同一个替换事务。普通左右移动与删除按字素；协议范围保留 UTF-16，来自平台的字节/码点单位必须显式转换。无效/越界/落在代理对中的平台范围不得拆字或错误写入，归一化或拒绝规则须在 TI-02 固定并有诊断；单行净化与现有行为兼容。

MaxLength继续以UTF-16长度计数，实际插入只在完整字素边界截断；选区替换释放的容量计入。预编辑可暂时长于剩余容量，不写绑定、不进入历史；最终结果按容量接受，不能截断已有未选中文本。全部被拒绝、空输入与结果未变不新增历史。

UI线程原子性：事务先捕获旧快照并计算候选，再写一次Binding；与实际回读值一致后才确认文档版本、选区和历史。Binding setter抛错时不得伪造已成功编辑；setter转换/拒绝写入时以实际回读值重同步，清理组合/历史而不是记录错误的逆操作。setter已产生的外部副作用不承诺回滚。严禁Build/Responsive builder写状态。

外部Binding内容变化、绑定来源替换、MaxLength语义变更：取消组合、递增会话/文档版本，清空历史并把选区限制到新文本；同值回读不得每帧清空历史。需区分自身事务确认与外部写入，不仅依赖字符串相等。绑定来源无法可靠识别时TI-02必须提出明确的内部来源标识/失效契约，并回归描述重建不会反复误清空。

## 7. 组合输入状态机

Idle → Composing →（Update若干次）→ Result/Cancel → Idle。原生一次消息可能同时带旧结果与下一段预编辑，也可能结果分段提交；适配层必须明确处理顺序，不能假定一次Start只有一次结果。

- Start记录焦点epoch、组合ID、文档版本、原替换区及选区快照。
- Update只构造显示串“已提交前缀 + 预编辑 + 已提交后缀”，不写Binding；原选中范围暂时由预编辑替代显示。替换区固定在对应版本上，不能每次按最新caret重新猜测。
- Result将当前接受的整段结果作为一个原子替换事务；一次结果事件是一项历史操作，不是逐字符历史。分段结果分别确认，后续预编辑按已提交文档重新定位；禁止用全会话快照覆盖已接受结果。
- Cancel恢复到最近已提交文档与该段开始前选区；已经确认的分段结果不会被取消掉。重复End/Cancel幂等。
- Session/focus epoch不匹配、已卸载、Disabled、失焦和旧版本事件一律不写入新客户端；结束时先切断旧事件归属，再异步通知平台取消，防同步回调串写。

策略固定：切换焦点、窗口失活、节点卸载/禁用、外部文本/绑定变化、Undo/Redo/Cut/Paste/SelectAll以及鼠标改选区，先取消未提交组合，再处理动作；复制只复制已提交选区。失焦保留已有TextField折叠选区的默认行为；单纯重新布局或同节点同绑定描述更新不能取消组合。

组合期间方向键、Backspace/Delete、空格、Enter和Escape优先由原生输入法处理；选词Enter不得冒泡成提交/激活，Escape先取消不得退出窗口，候选导航不得移动已提交文档caret；Tab先按输入法已消费结果决定是否遍历。须覆盖结束同一原生按键仍进入KeyDown回调的情况，不能只检查此刻是否Composing。普通字符、键盘事件与IME结果的单一来源/去重基于消息归属及序列，禁止按相同字符串或固定时间窗全局吞字符。

## 8. 绘制、命中与候选窗定位

预编辑使用真实Skia排版并绘制下划线/活动段，复用当前字体、颜色、透明度和裁剪链；选区、组合caret、已提交caret、点击命中共享一套显示串到文档位置的映射。显示串与已提交文本缓存必须区分。内部组合caret不一定与文档字素边界等同，平台单位转换后按排版可用caret规则处理，不能破坏原生状态。

候选窗由系统绘制，框架只发布有效caret和排除区。发布几何来自最终排版原点+真实caret，包含TextField横向ScrollX、祖先滚动、Padding/Frame、裁剪与像素吸附；不可只用矢量caret被夹取后的X掩盖文本错位。被完全裁出/隐藏的客户端撤销锚点或暂停会话，不把候选定位到窗口原点。

核心矩形为窗口内容区逻辑像素；宿主按现有窗口/逻辑/framebuffer三空间转换至平台要求的客户区或屏幕单位。候选锚点在caret、组合、字体、布局、窗口位置、DPI/屏幕和滚动变化时更新，重复同值不持续唤醒。系统候选UI可能自行避让屏幕边缘，验收记录请求锚点与实际避让，不机械要求最终候选框每像素相等。

## 9. 撤销重做与快捷键

历史与TextField运行时节点同寿命；AdaptiveStack/Flow重排保留，Responsive真正卸载清理。默认最多100条，另限制历史保留文本总量1,048,576个UTF-16 code unit（前后片段均计数），内部可配置；超限淘汰最老完整事务。单次编辑大于总预算仍执行但清空历史且不保存该项，不保留无法达到的redo；日志不包含用户原文。

同类相邻普通键入、连续同方向删除可在500ms单调时钟窗口合并，窗口内仍须满足范围连续、选区无跳转、来源相同。光标/选区移动、失焦、外部更新、剪贴板、组合结果及Undo/Redo打断合并。净化后无变更不入栈；撤销后新编辑清空redo；空栈无副作用。

Undo/Redo恢复准确文本和前后选区/方向，再保证caret可见。历史不把预编辑更新入栈。Windows/Linux为Ctrl+Z、Ctrl+Y及Ctrl+Shift+Z；macOS为Command+Z/Command+Shift+Z。输入法与平台保留键优先，AltGr不得误判成编辑快捷键。不要继续用Control或Meta任意一个即通用命令的逻辑覆盖所有平台。事件消费结果须传回宿主，保留无焦点时已有退出快捷键。

| IME结果与GLFW字符重复 | 固定消息所有权、序列追踪、分段/补充平面字符测试，不按文本/时间猜测 |
| 结束后的Enter/Esc继续执行宿主动作 | 完整按键生命周期消费到宿主，测试end与keydown交错 |
| 重建/焦点导致串写或丢字 | 会话epoch+文档版本，取消幂等、旧事件隔离、绑定来源识别 |
| 候选窗漂移或旧纹理缩放 | 统一显示几何，实际DPI/滚动/原生窗口验证与独立像素比较 |
| 历史内存增长、错误回滚绑定 | 双上限、实际回读确认、异常/拒绝清理与资源计数 |

## 13. 参考资料与事实边界

以下为2026-10-17核对的官方入口；平台路线属于待验证设计，不由资料存在推导本项目已经支持。

- [GLFW 3.4输入指南](https://www.glfw.org/docs/3.4/input_guide.html)：字符回调提供Unicode字符流，实际加载版本仍需TI-01核对。
- [WM_IME_COMPOSITION](https://learn.microsoft.com/en-us/windows/win32/intl/wm-ime-composition)：消息可带组合状态/结果标志，不能只读取按键文本。
- [ImmGetCompositionStringW](https://learn.microsoft.com/en-us/windows/win32/api/imm/nf-imm-immgetcompositionstringw)：宽字符查询的缓冲长度/返回量仍以字节计，适配层须显式处理。
- [ImmSetCandidateWindow](https://learn.microsoft.com/en-us/windows/win32/api/imm/nf-imm-immsetcandidatewindow)：系统候选窗口位置入口，具体输入法是否采用须实测。
- [Text Services Framework](https://learn.microsoft.com/en-us/windows/win32/tsf/text-services-framework)：Windows另一类文本服务接入，需要原型判断是否必要。
- [Apple NSTextInputClient](https://developer.apple.com/documentation/appkit/nstextinputclient)：macOS路线调查入口，未声明已与当前GLFW视图安全接通。
- [Wayland text-input-v3协议源](https://gitlab.freedesktop.org/wayland/wayland-protocols/-/blob/main/unstable/text-input/text-input-unstable-v3.xml)：TI-01后续调查入口，本次网页访问被站点拦截，未据其内容作兼容结论。
