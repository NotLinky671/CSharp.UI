## 目标与范围

提供保留滚动位置的容器与可显示图片的内容视图，覆盖常见桌面布局需求。

首版每个 ScrollView 选择一个滚动轴，不实现列表虚拟化；Image 先支持本地文件和应用资源，不引入网络下载。

## 前置依赖

- 前置任务：[任务 07：OpenGL 命令渲染与 GPU 资源管理](07-opengl-renderer.md)、[任务 09：输入分发、指针捕获与焦点](09-input-and-focus.md)。
- 接入依据：使用任务 05 的测量和命令生成、任务 07 的纹理与裁剪、任务 09 的滚轮和命中；节点身份由任务 03 提供。

## 实施清单

- [x] 实现 ScrollView 在滚动方向测量内容、在横向使用视口约束，并将内容裁剪至有限视口。
- [x] 滚轮改变滚动偏移，限制在有效范围；视口或内容变化重新限制偏移，节点复用保留位置。
- [x] 滚动偏移同步影响绘制与命中坐标；嵌套滚动容器根据是否消费事件分发滚轮。
- [x] 本任务负责实现任务 02 图片资源服务契约对应的 CPU 解码；在 CSharp.UI.Text 中接入已固定版本的 SkiaSharp 及所需原生资产，不假设任务 08 已提供图像服务。实现 Image 加载、自然尺寸测量与保持比例的尺寸适配，纹理上传仍由 OpenTK 完成。
- [x] 明确文件不存在或无效图片的诊断；按资源所有权缓存和释放 CPU 位图、纹理，防止重建时重复上传。
- [x] 补充滚动列表和固定资源图片场景，将两类视图接入现有布局与绘制流程。

## 公开 API 与交接

交付 ScrollView 的单轴配置以及 Image 的资源与尺寸适配 API；滚动状态保存在运行时节点，不要求应用自行保存偏移。图片解码服务由本任务交付并由宿主组装，任务 08 负责文字排版，二者共享版本基线但不存在新增前置依赖。

交付实现、对应测试及必要使用说明；所有测试与实现同步完成。后续任务消费本任务契约时保持原计划的模块边界。
